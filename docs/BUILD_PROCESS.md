# Build Process Documentation

## Overview

This document describes the build script pattern used to convert JSON data files into frozen JavaScript constants. This approach provides type-safe, edit-friendly data management while maintaining fast runtime performance.

## Pattern

### Data Flow

1. Edit source JSON file in `src/data/`
2. Run build script (manual or automatic via npm scripts)
3. Script generates frozen constant in `src/constants/`
4. Components import from generated constants

### Benefits

- **Edit-friendly**: Modify JSON without touching code
- **Type-safe**: Generated JS constants, not runtime JSON parsing
- **Fast**: No fetch calls or async loading
- **Build-time validation**: Errors caught before runtime
- **Immutable**: Object.freeze() prevents accidental mutations

## Implementation Pattern

### 1. Source Data File

**Location:** `src/data/{feature}.json`  
**Purpose:** Editable data source (manually maintained)

### 2. Build Script

**Location:** `scripts/build-{feature}.js`  
**Purpose:** Transform JSON → frozen constant

**Template:**

```javascript
import fs from 'fs'
import path from 'path'
import { fileURLToPath } from 'url'

const __filename = fileURLToPath(import.meta.url)
const __dirname = path.dirname(__filename)

const sourceJsonPath = path.join(__dirname, '../src/data/{feature}.json')
const outputPath = path.join(__dirname, '../src/constants/{feature}.js')

try {
  const data = JSON.parse(fs.readFileSync(sourceJsonPath, 'utf-8'))
  
  const fileContent = `// Auto-generated by scripts/build-{feature}.js
// Do not edit manually - edit src/data/{feature}.json instead

export const {featureName} = Object.freeze(${JSON.stringify(data.{featureName}, null, 2)})
`
  
  fs.writeFileSync(outputPath, fileContent, 'utf-8')
  console.log('✅ {Feature} constant generated successfully')
} catch (error) {
  console.error('❌ Error building {feature}:', error.message)
  process.exit(1)
}
```

### 3. Generated Constants File

**Location:** `src/constants/{feature}.js`  
**Purpose:** Auto-generated frozen constant (committed to git)  
**Note:** Contains warning comment to edit JSON instead

### 4. Package.json Integration

```json
{
  "scripts": {
    "build:{feature}": "node scripts/build-{feature}.js",
    "dev": "npm run build:{feature} && vite",
    "build": "npm run build:{feature} && vite build"
  }
}
```

## Usage in Components

```javascript
import { projects } from '../constants/projects'

function MyComponent() {
  // Data immediately available, no loading state needed
  return (
    <div>
      {projects.map(project => (
        <div key={project.id}>{project.name}</div>
      ))}
    </div>
  )
}
```

## Git Management

- **Source JSON files** (`src/data/*.json`): Committed
- **Build scripts** (`scripts/build-*.js`): Committed
- **Generated constants** (`src/constants/*.js`): Committed
  - Reasoning: Personal portfolio, simplifies deployment
  - Alternative: Add to `.gitignore` for team projects

## Adding New Build Processes

1. Create source JSON in `src/data/`
2. Create build script in `scripts/` (use template above)
3. Add `build:{feature}` command to package.json
4. Update `dev` and `build` scripts to include new build command
5. Run build script to generate initial constants file
6. Import and use in components

## Troubleshooting

### Build script fails

- Check JSON syntax validity
- Ensure source file path is correct
- Verify Node.js supports ES modules

### Data not updating

- Ensure build script ran successfully
- Check if watching correct file in dev mode
- Restart dev server after manual script runs

### Import errors

- Verify generated file exists in `src/constants/`
- Check export name matches import
- Ensure build script completed without errors
